# Systematic Debugging - 系统化调试

## 何时触发

- 代码报错或产生非预期结果
- 测试失败
- 行为与预期不符
- 用户说"帮我看看这个 bug"

## 工作流程

### 禁止：直接改代码
不要在没搞清根因之前就动手改代码。

### 第一步：收集证据
- 读取报错信息和堆栈
- 查看相关日志
- 复述问题：「目前的情况是……」

### 第二步：定位根因
- 提出 2~3 个可能的假设
- 逐一验证或排除
- 找到真正的根因（不是表面现象）

### 第三步：提出修复方案
- 说明修复思路
- 评估修复影响范围
- 和用户确认后再修改

### 第四步：验证修复
- 复现原问题确认已修复
- 运行相关测试确保无回归
- 检查是否引入了新问题

## 输出格式

```
## 问题描述
[具体报错信息或异常行为]

## 假设
1. [可能原因A] → 验证方法: ...
2. [可能原因B] → 验证方法: ...

## 根因
[确认的根本原因]

## 修复方案
[准备怎么改，影响哪些文件]

## 验证结果
[修复后的测试结果]
```

## 核心原则：先诊断，再治疗
