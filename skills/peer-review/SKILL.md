# Peer Review - 学术论文同行评审

## 何时触发

- 用户说"审一下这篇论文"
- 用户要求评价某篇文献的方法论质量
- 写综述时需要评估纳入研究的质量
- 投稿前自审自查
- lit-agent 的 review 命令生成综述后，需要对单篇做质量评估

## 评审维度

### 1. 研究设计 (Study Design)
- 问题/假设是否清晰定义？
- 实验设计是否合理（对照、样本量、随机化）？
- 方法是否可复现（试剂/设备/软件版本是否交代）？

### 2. 数据分析 (Data Analysis)
- 统计方法是否正确？
- 多重检验是否校正（Bonferroni/FDR）？
- 效应量是否报告（不只 p 值）？
- 数据可视化是否恰当？

### 3. 结论有效性 (Validity of Conclusions)
- 结论是否被数据支撑？
- 是否承认局限性？
- 是否过度推广（overclaiming）？
- 替代解释是否被讨论？

### 4. 文献引用 (Literature Context)
- 是否遗漏关键先前工作？
- 引用是否准确（篇名/作者/年份）？
- 是否恰当区分自己的贡献与前人工作？

### 5. 写作质量 (Writing Quality)
- 逻辑是否清晰连贯？
- 图表是否自明（标签、图例、单位完整）？
- 术语使用是否一致？

### 6. 伦理与透明度 (Ethics & Transparency)
- 伦理审批/知情同意是否声明？
- 利益冲突是否披露？
- 数据/代码是否可获取？

## 工作流程

### 第一步：通读
先快速浏览标题→摘要→图表→结论，形成初步印象。

### 第二步：逐段精审
按上面的六个维度逐条检查，发现问题随时记下具体行/段位置。

### 第三步：给出总评
综合各维度，给出明确的接受/修改/拒稿建议。

## 输出格式

```markdown
## 论文评审报告

**论文**: [标题]
**期刊/年份**: [期刊, 年份]
**审稿日期**: [日期]

### 总体评价: [接受 / 小修 / 大修 / 拒稿]

### 优点
- [列举 2-4 条论文做得好的地方]

### 主要问题 (Major Issues)
1. **[维度: 具体问题]**
   - 位置: [第X段/Figure X]
   - 描述: ...
   - 建议: ...

### 次要问题 (Minor Issues)
- [格式/措辞/引用等小问题]

### 统计与方法论特别检查
- 样本量是否足够: [是/否/存疑]
- 统计方法: [是否正确使用]
- 多重检验: [是否校正]
- 效应量: [是否报告]

### 综合建议
[用 2-3 句话总结修改方向]
```

## 评审严重程度标记

| 标记 | 含义 |
|------|------|
| 🔴 致命 | 结论不成立，需要重做实验/分析 |
| 🟡 重大 | 需要实质性修改后才能接受 |
| 🟢 轻微 | 修改不改变结论 |
| 💡 建议 | 可选改进 |

## 核心原则

- **具体**：指哪一段、哪个图、哪个数据有问题，不要泛泛而谈
- **建设性**：不仅指出问题，还要给出怎么改
- **公正**：不因研究方向不喜欢而贬低，就事论事
- **区分事实与意见**：事实错误标注为"事实错误"，方法论偏好标注为"建议"
