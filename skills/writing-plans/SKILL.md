# Writing Plans - 编写执行计划

## 何时触发

- 需求已讨论清楚，准备开始实现
- 用户要求"帮我规划一下"
- 任务涉及多个步骤或文件修改
- 需要在开始前有书面计划

## 工作流程

### 第一步：拆分任务
把大需求拆成 bite-sized 的小任务，每个任务：
- 单一职责（只做一件事）
- 可独立验证
- 有明确的完成标准

### 第二步：排序与依赖
- 标注任务之间的依赖关系
- 排定执行顺序
- 标注哪些任务可以并行

### 第三步：风险评估
- 标出高风险任务
- 给出风险缓解建议
- 标注需要用户确认的决策点

## 输出格式

```
## 执行计划

### 步骤 1: [任务名] [优先级: 高/中/低]
- 做什么:
- 涉及文件:
- 完成标准:
- 依赖: 无 / 依赖步骤X

### 步骤 2: ...
- ...

## 依赖关系图
步骤1 → 步骤2 → 步骤3
         ↘ 步骤4 (可并行)

## 风险提示
- 步骤X 风险较高，原因: ...
```

## 核心原则：先有计划，再动手
