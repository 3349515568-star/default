# Brainstorming - 需求与方案探讨

## 何时触发

**在任何创造性工作之前必须调用此技能**，包括但不限于：
- 创建新功能
- 构建新组件
- 添加新能力
- 修改现有行为
- 用户提出模糊需求

## 工作流程

### 第一步：理解意图
不要直接写代码。先向用户提问，把需求搞清楚：
- 这个功能要解决什么问题？
- 目标用户是谁？
- 有没有现有代码或项目可以参考？

### 第二步：探索方案
- 列出至少 2~3 个可行的技术方案
- 对比每个方案的优缺点
- 给出推荐方案及理由

### 第三步：确认边界
- 明确哪些要做、哪些不做
- 确认约束条件（性能、兼容性等）
- 和用户确认后再进入实现阶段

## 输出格式

按以下结构输出：

```
## 需求理解
[用1-2句话总结你理解的需求]

## 方案对比
| 方案 | 优点 | 缺点 |
|------|------|------|
| A    | ...  | ...  |

## 推荐方案
[推荐哪个方案，为什么]

## 边界确认
- 做: ...
- 不做: ...
```

## 核心原则：先讨论，再动手
