# Verification Before Completion - 完成前验证

## 何时触发

- 任何任务即将完成时
- 用户问"做完了吗"或"搞定了吗"
- 代码修改完成后
- 提交代码之前

## 核心规则

**禁止在未验证的情况下声称任务完成。**

在你对用户说"搞定了"之前，必须：

### 第一步：运行验证命令
根据项目类型选择验证命令：
- Python: `python -m pytest` 或运行相关测试文件
- Node.js: `npm test` 或 `npm run lint`
- 通用: 运行项目现有的测试套件
- 至少运行一次完整的功能验证

### 第二步：检查验证输出
- 查看是否有失败或警告
- 确认输出符合预期
- 如果失败，先修复再重新验证

### 第三步：人工检查清单
- [ ] 所有测试通过
- [ ] 没有引入明显的 lint 错误
- [ ] 修改的文件与任务匹配
- [ ] 没有遗留的调试代码
- [ ] 用户的需求是否都满足了

### 第四步：汇报结果
只有以上都通过后，才能向用户汇报完成。

## 输出格式

```
## 验证结果
- 测试: ✅ 全部通过 (3/3)
- Lint: ✅ 无新增错误
- 功能验证: ✅ 符合预期

任务完成。
```

## 核心原则：验证通过才能说完成
