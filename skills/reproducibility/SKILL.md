# Reproducibility - 可复现性检查清单

## 何时触发

- 用户说"帮我检查这篇论文/这个实验能不能复现"
- 准备投稿前做自查
- 审稿时怀疑某篇论文的方法学描述不够
- 需要准备数据共享方案

## 检查维度

### 1. 实验复现性 (Experimental)

| 检查项 | 是否满足 |
|--------|----------|
| 试剂：厂商 + 货号 + 批号 | ☐ |
| 抗体：厂商 + 货号 + 稀释比例 + 验证方式 | ☐ |
| 细胞系：来源 + 传代次数 + 支原体检测 | ☐ |
| 动物：品系 + 性别 + 年龄 + 体重 + 饲养条件 | ☐ |
| 仪器：型号 + 关键参数 + 软件版本 | ☐ |
| 对照组：阳性对照 + 阴性对照 + 溶剂对照的明确描述 | ☐ |
| 样本量：每组的 n 数 + 是技术重复还是生物重复 | ☐ |
| 随机化：是否描述 + 方法（简单随机/分层/区组） | ☐ |
| 盲法：是否描述谁对什么设盲 | ☐ |
| 排除标准：是否预设 + 是否有数据点被排除 | ☐ |

### 2. 统计复现性 (Statistical)

| 检查项 | 是否满足 |
|--------|----------|
| 统计方法：明确写出用的是什么检验 | ☐ |
| 前提条件：t 检验的正态性/方差齐性是否检验 | ☐ |
| 多重检验校正：是否做了（Bonferroni/FDR） | ☐ |
| 效应量：是否报告（Cohen's d / η² / OR + CI） | ☐ |
| 样本量计算：是否做了（power analysis）还是事后合理化 | ☐ |
| 软件：统计软件 + 版本 + 包版本 | ☐ |
| p 值：精确值还是 <0.05 就停 | ☐ |
| 缺失数据：如何处理（删/插补/模型） | ☐ |

### 3. 计算复现性 (Computational)

| 检查项 | 是否满足 |
|--------|----------|
| 代码：是否开源 + 版本号 + 永久链接（GitHub + Zenodo DOI） | ☐ |
| 环境：是否提供 requirements.txt / Dockerfile / conda env | ☐ |
| 数据：原始数据是否可获取（SRA/GEO/Figshare/Zenodo） | ☐ |
| 参数：关键参数是否写明（seed, learning rate, 阈值） | ☐ |
| 随机种子：是否固定 | ☐ |
| 中间文件：是否保留或可重新生成 | ☐ |
| README：是否有使用说明 | ☐ |

### 4. 数据共享 (Data Sharing)

| 检查项 | 是否满足 |
|--------|----------|
| 原始数据存放在公共仓库 | ☐ |
| 数据有 DOI（可引用） | ☐ |
| 数据字典/README 描述了每个变量 | ☐ |
| 数据使用许可明确（CC-BY / CC0） | ☐ |
| 敏感数据有脱敏/受控访问方案 | ☐ |

## 分级标准

### 🟢 可复现
所有必选检查项（试剂、样本量、统计方法、代码、数据）全部满足。

### 🟡 部分可复现
关键信息有缺失但可推断，或部分数据未公开但有合理理由（如病人隐私）。

### 🔴 不可复现
方法学描述严重不足，关键试剂/数据/代码不可获取，统计方法有明显问题。

## 输出格式

```markdown
## 可复现性审计报告

**论文/项目**: [标题]
**审计日期**: [日期]

### 总体评级: 🟢 可复现 / 🟡 部分可复现 / 🔴 不可复现

### 实验复现性
- ✅ 已满足: [列出]
- ❌ 缺失: [列出 + 建议]

### 统计复现性
...

### 计算复现性
...

### 数据共享
...

### 改进建议
1. [最优先要补充的一项]
2. [其次]
```

## 连接 lit-agent

- lit-agent 的 validate 命令已验证的 DOI 可以用来检查参考文献的准确性
- lit-agent 检索到的文献如果在方法学上不完整，用这个 skill 标注"方法学信息不足"
- 综述里每篇纳入的文献可以做一次快速复现性评估，作为质量权重的依据
