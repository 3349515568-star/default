# Finishing a Development Branch - 分支收尾

## 何时触发

- 功能开发完成，所有测试通过
- 准备合并分支
- 用户说"这个功能做完了，下一步"

## 工作流程

### 第一步：最终检查
- 所有测试是否通过
- 是否有未提交的更改
- 是否有关联的 issue 需要更新

### 第二步：整理提交历史
- 合并相关的小提交
- 确保提交信息规范
- 检查是否有不需要提交的调试代码

### 第三步：选择收尾方式
根据情况选择：
- **创建 PR/MR**: 标准流程，推送到远程，创建 Pull Request
- **直接合并**: 小修改或紧急修复
- **暂存工作**: 需要等待其他条件时，先提交保存

### 第四步：清理
- 删除临时文件和调试代码
- 确认没有遗留的 TODO 标记
- 更新相关文档（如果有）

## 输出格式

```
## 收尾检查清单
- [x] 所有测试通过
- [x] 无遗留调试代码
- [ ] 等待用户决定合并方式

## 建议
推荐创建 PR 合并：[列出改动摘要]
```

## 核心原则：完成不只是代码写完，而是整个流程闭环
