# Autoskill - 工作流 → Skill 打包

## 何时触发

- 用户说"帮我把这个流程打包成一个 skill"
- 一个操作过程重复出现了 3 次以上，值得固化
- 需要和团队共享一个标准操作流程
- 想把手动繁琐的多步操作变成一句指令

## 什么是值得打包成 Skill 的工作流

判断标准：
- 有明确的输入和输出
- 步骤 >= 3，且顺序重要
- 会重复使用（不是一次性的）
- 需要保持一致性（换人做也要做对）

## Skill 文件的格式

每个 skill 是一个文件夹，内含一个 `SKILL.md`：

```markdown
---
name: "skill-name"
description: "一句话描述，用于自动匹配触发。当用户说 XX 时调用。"
---

# Skill 中文名 - 简要说明

## 何时触发
[列举会触发这个 skill 的用户说法]

## 核心流程/框架
[1-2-3 步的核心逻辑]

## 输出格式
[标准化输出模板]

## 注意事项
[容易踩的坑]
```

## 从你的 lit-agent 工作流打包示例

### 工作流："每周文献速报"
你现在的步骤：
1. 在 lit-agent 跑 `py lit_agent.py discover --query "你的领域" --source all`
2. 挑出评分 ≥ 7 的文献
3. 让 LLM 用中文写 3 句话总结
4. 生成一个 markdown 表格方便扫读

打包成 skill 后，只需一句："帮我出本周的 CRISPR 文献速报"，agent 就能记住这个四步流程。

### 工作流："投稿前自查"
你现在的步骤：
1. 跑 peer-review skill 审自己的手稿
2. 跑 citations.py 验证参考文献 DOI 是否有效
3. 用 scientific-writing skill 检查格式是否符合目标期刊
4. 用 mermaid-diagrams 检查图的标注是否完整

打包成 "manuscript-submission" skill 后，一句指令跑完整个自查。

## Skill 命名规范

| 模式 | 示例 | 适用 |
|------|------|------|
| 动名词 | `peer-review` | 单个任务 |
| 领域-任务 | `lit-agent-discover` | 项目特定的 |
| 工具名 | `mermaid-diagrams` | 围绕工具的能力 |
| 流程名 | `manuscript-submission` | 多步骤工作流 |

## 打包流程

### 第一步：记录原始工作流
用户把完整操作说一遍，agent 记录每一步的输入、输出、注意事项。

### 第二步：抽象成通用模板
把具体参数（如"CRISPR"）替换成变量（如"query"）。

### 第三步：写 SKILL.md
套用标准格式，特别是"何时触发"的触发词要多写几个变体——这是 agent 能否自动匹配的关键。

### 第四步：测试
用一句话触发这个 skill，看 agent 是否按预期走了完整流程。

## 输出格式

```markdown
## Skill 打包结果

已将你的工作流打包为 skill `[skill-name]`

**触发词**: "[列举 3-5 种说法，用户说任意一个就会自动匹配]"

**使用方式**: 直接说"帮我[触发词]", agent 会按标准流程执行。

**文件位置**: `.trae/skills/[skill-name]/SKILL.md`

**流程概览**:
1. 步骤一: ...
2. 步骤二: ...
3. ...

**可配置参数**:
- `参数1`: [默认值] - [说明]
- `参数2`: [默认值] - [说明]
```

## 注意事项

- 一个 skill 只做一件事，不要塞太多不相关的步骤
- 触发词要覆盖用户自然说话的方式，不要只有一种说法
- 步骤描述要具体，用"做了什么"而非"应该做什么"
- 如果流程里涉及外部工具（如 lit-agent CLI），注明需要先装什么依赖
