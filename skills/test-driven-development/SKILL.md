# Test-Driven Development - 测试驱动开发

## 何时触发

- 用户明确要求 TDD
- 开发新功能模块
- 需要保证代码质量的场景
- 用户说"先写测试"

## TDD 循环：Red → Green → Refactor

### Red 阶段：先写失败的测试
1. 分析需求，确定测试用例
2. 写出测试代码（此时功能代码还不存在）
3. 运行测试，确认测试失败（红色）
4. 这一步确保测试本身是正确的

### Green 阶段：最小实现
1. 写出刚好能让测试通过的最少代码
2. 不要多想未来的需求
3. 运行测试，确认通过（绿色）

### Refactor 阶段：重构优化
1. 消除重复代码
2. 改善代码结构
3. 运行测试确认重构后依然通过

## 测试要求

- 覆盖正常路径
- 覆盖边界条件
- 覆盖错误处理
- 每个功能点至少一个测试

## 输出格式

```
## 测试用例
### 测试1: [测试名称]
- 输入: ...
- 预期输出: ...

## RED: 测试编写完成，当前失败 ❌

## GREEN: 最小实现完成，测试通过 ✅

## REFACTOR: 重构完成，测试仍通过 ✅
```

## 核心原则：先写测试，后写代码
